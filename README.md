# 明约 · 合同阅读工作台

面向中国大陆培训、求职辅导合同的单用户本地应用。`hk-edition` 分支另有香港住宅租约版，见文末“香港版”一节。用日常中文解释条款，保留原文引用，提供沟通草稿。需求原件位于 contract-agent-mvp-prompt.md；本次用户授权扩展了原MVP的六项工具。

## 启动

双击桌面“启动合同检测助手.bat”。它调用项目 launch.ps1，后台启动并检查服务，地址为 http://127.0.0.1:8000/ 。已有服务时不会重复启动。项目 start.bat 也可在前台运行。

全新环境运行 setup.ps1，安装 backend/requirements-lock.txt 中的Python依赖、执行npm ci并构建前端。SDK版本使用Python 3.11、Node 24。密钥仅放在 backend/.env。

当前使用DeepSeek兼容Chat Completions接口。可配置 MODEL_BASE_URL、MODEL_API_KEY、MODEL_NAME、MODEL_RESPONSE_FORMAT、MODEL_TIMEOUT_SECONDS、MAX_ANALYSIS_CHARS。MODEL_TRUST_ENV=false 是本机模型连接设置，不关闭TLS证书验证。承诺对照要求模型支持JSON输出。

## 日常使用

1. 导入PDF、DOCX、图片，或粘贴合同。扫描页在本机OCR；混合页可选择整份OCR。
2. 核对文字、金额和对应服务。修改后保存新版本，再确认分析范围。
3. 同意发送脱敏正文与背景后生成真实报告。演示报告不会判断合同风险。
4. 使用上方工具。需要下次继续看时，进入报告历史，勾选本机保存并保存快照。

## 六项工具（2026-10-25）

## 数据保存

- 原文件在内存解析，不写磁盘，不发给模型。OCR模型随Python包装入，运行识别不联网。
- 未保存文档、版本、报告和工具结果在内存SQLite保留约1小时，关闭后端即丢失；最多20份临时文档。
- 只有主动保存才写入 data/history.sqlite3，包含合同文字等私密内容，未加密，保留至主动删除。可用 HISTORY_DB 指定其他本机路径，切勿公开分享数据目录。
- 清除临时文档不会删除历史；历史删除不可在应用中撤销。JSON导出是备份，目前不提供JSON导入。
- 主报告发送脱敏正文及背景；承诺对照发送脱敏正文及销售说法。规则脱敏不能发现所有姓名、地址等隐私，请先人工核对并确认发送。
- 法规检索只在本机进行，不发送检索词；更新仅请求固定官方URL，缓存不含合同。
- 应用日志不主动记录正文或密钥，启动器关闭访问日志。只监听127.0.0.1，无登录及多用户隔离，不适合直接公开部署。

## 限制与实现

单文件10MB，PDF最多80页，一次OCR最多20页。解析子进程最长180秒，超时终止；建议长扫描件拆分。图片最多3000万像素，OCR时限制尺寸。正文提取最多25万字符，主报告及承诺对照正文默认上限24000字符，不静默截断。DOCX展开最多30MB、2000个ZIP条目，页眉/页脚/嵌套表格/图片/批注/修订痕迹等仍未覆盖。版本比较两版共10万字符。历史列表显示最近200条。

引用使用编号片段，模型仅选择block_id/quote_id，后端回填原话与位置，拒绝虚假引用并有限重试。引用核验保证出处存在，不保证推理正确。法规原文保留官方措辞，其余报告尽量用通俗中文。

主要代码：backend/app/main.py（API）、analysis.py（主报告与引用）、contract_tools.py（承诺/退款/比较）、ocr.py及parsing.py（解析）、store.py及history.py（临时与历史）、legal.py及legal_corpus.json（法规选编）；frontend/src/ToolsPanel.vue（工具界面）、App.vue（三步流程）。

尚未实现：长合同分段及跨段分析、表格几何重建、保证识别手写、多用户认证、收费与公开部署。

使用官方 PyPI 包 openjiuwen==0.1.18（Python>=3.11,<3.14），独立环境 .venv-jiuwen；旧 .venv 保留，启动脚本已切换至SDK环境。setup.ps1 使用 py -3.11 创建新环境并安装锁定依赖。

backend/app/jiuwen_workflow.py 定义确认、分析、承诺、法规、汇总五个WorkflowComponent节点，使用Workflow/WorkflowCard/add_connection/create_workflow_session/invoke真实调度。每个请求创建独立图和会话，执行上限1800秒。节点不自动重试付费模型调用；沿用分析适配器原有受限重试。SDK收到的输入输出只有状态，正文及报告存放在请求内闭包，不进入SDK跟踪载荷或检查点。当前不提供跨进程断点恢复。

主报告失败会阻断后续业务操作；承诺和法规辅助失败保留报告。DeepSeek仍是模型供应商，与openJiuwen工作流引擎并不冲突。健康检查和界面显示SDK版本，缺少SDK时启动失败，不静默切回原生编排。

## 香港版（hk-edition 分支，Hong Kong Techathon+ 准备）

首期场景是香港住宅租约，首批用户是来港留学生（以内地学生为主）和新来港人士。大陆版功能保持可用。

### 启动与地区配置

- `REGION=cn|hk` 决定地区，可写在 `backend/.env`，也可以设为环境变量；本分支默认 `hk`。填写未知值时服务启动即报错，不会静默回退。
- 启动方式和大陆版相同（`launch.ps1` / `start.ps1`）。想用大陆版，在 `backend/.env` 加一行 `REGION=cn`。
- 地区相关内容集中在 `backend/app/profiles/`（`cn.py`、`hk.py`）：提示词、事实字段、脱敏规则、法规来源、货币、草稿渠道、示例、工具与界面文案。前端通过 `GET /api/profile` 读取，不包含提示词。
- `REGION=cn` 时，发给模型的提示词、脱敏结果、演示报告、法规检索和引用片段，与改造前逐字节一致（指纹比对）。

### 功能

| 功能 | 行为 | 边界 |
|---|---|---|
| 租约分析 | 10 项租约事实；检查租期与生约/死约、按金、费用分担、维修、分租、收款主体、业主进入与出售、交还单位、续租、临约与正式租约是否一致 | 不做诈骗判断，不判断业主身份真伪、租约效力或扣费是否合法；只写合约里有什么、缺什么，并建议自行核实（例如查册） |
| 输出语言 | 简体中文（默认）、繁體中文、English；引用保持英文或繁体原文逐字不变 | 固定取值（等级、状态、“未发现明确约定”）保持中文 |
| 沟通草稿 | WhatsApp / 微信 / 电邮，写给业主或代理 | 由你检查后自行发送 |
| 业主 / 代理承诺对照 | 逐条比较口头、聊天里的说法与租约，附原文 | 不认定口头说法已构成租约 |
| 按金与退租试算 | 按金、预付租金、欠租、确认的扣减项（各附依据）、罚则（若干月租 / 固定金额 / 没收按金）；用 Decimal 计算，展示算式，给出两种情景 | 不猜金额，不判断扣费是否合法，负余额不等于欠款 |

| 签约前核对清单 | 依据真实报告和租约原文按规则生成，不联网；每项附原文或注明“本次正文未找到” | 不判断身份或真伪 |
| 求助渠道 | 差饷物业估价署、地产代理监管局、土地注册处（查册）、消费者委员会、小额钱债审裁处、免费法律咨询计划 | 以官方网站为准 |

### 脱敏（香港）

在大陆规则之外，新增：

- 香港身份证：带括号的格式在任何位置都脱敏，不带括号的只在有标签时脱敏；
- 护照号：有标签时脱敏；
- 电话：带 `+852` 或有标签的 8 位号码；
- 银行账号：有标签，或符合 `NNN-NNNNNN-NNN` 格式；
- 卡号：通过 Luhn 校验的才脱敏；
- 姓名：英文字段标签（Landlord / Tenant / Name 等）、称谓和中文姓名标签后面的姓名，替换为本次运行内一致的化名，便于比较收款人与出租人是否为同一人。

刻意保留不脱敏的内容：没有标签的 8 位数字（常是金额、日期或单号）、金额、物业地址、公司名。发送前和脱敏预览页会提示“地址和没有标签的姓名会发送给模型，可手动删改”。

### 法规来源与覆盖范围

**香港法规库尚未建立。** 按要求，条文只能从香港电子版法例（https://www.elegislation.gov.hk）抓取，但开发机访问 eLegislation 和 gov.hk 时 TLS 握手失败（2026-10-31、2026-11-01 两次复测）。因此没有写入任何条文，没有凭记忆补写，也没有关闭证书验证。

目前法规检索在 hk 下返回空库并如实提示；“更新官方来源”不会写入文件。候选条例（Cap. 7、Cap. 511 及其附属规例、Cap. 117、Cap. 71）待网络可用或获得官方下载文件后再逐条核对。
